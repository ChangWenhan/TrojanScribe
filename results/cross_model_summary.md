# Cross-model transfer on D_c (100 frozen questions per dataset)

Generated by `experiments/summarize_cross_model_dc.py` from the judged files in `results/` (judge: gpt-oss-20b). Same D_c, same denominator and same scoring as the main table and the ablations.

How to read it: each cell is one model's poison texts replayed into a different victim's knowledge base (that victim's own benign snapshot underneath, its own clean run as the 'before the attack' reference). The diagonal uses the same definition, so transfer and self-attack are directly comparable. The success and flip matrices are counts out of the same 100 questions; the ASR matrix is a rate over the questions that victim answered correctly before the attack, printed with both counts (`adopted/answerable = rate`).

**How to read this**

- **success** = the victim no longer returns the correct answer (it states a wrong answer, or stops answering).
- **of which really flipped** = the narrower event: the victim now states a specific wrong answer. The rest of the success count is the victim falling silent, which is reported separately because it is not a knowledge rewrite.
- **strict ASR** = the answer states the specific injected wrong answer, counted only over the questions that victim answered correctly before the attack (`adopted/answerable = rate`), so it is always <= flip. A victim with a low clean score has a small denominator; the counts are printed so that is never hidden.
- **diagonal** = the same model writing and being attacked; it is the main table's row, repeated here so transfer can be read as a difference against self-attack.
- `-` = that cell has not finished yet.

Consistency: the cross-model blocks in `results/ablation_summary.md` are produced from the same function, so the two files cannot disagree.
